# 动态面试与能力画像分阶段实施计划

- 版本：v0.1
- 日期：2026-10-10
- 状态：阶段 0 已建立工程基线和待人工审定样例；阶段 1 本地影子评价切片已实现。PostgreSQL 实测与语义质量门槛尚未完成。详见[本次验收记录](../reports/evidence-phase01/README.md)。
- 依据：[全链路设计](../specs/adaptive-interview-evidence-profile-spec.md)、[岗位准备页设计](../specs/job-interview-preparation-spec.md)。

## 1. 顺序与原则

先形成“回答证据 → 动态追问 → 局部画像”的可验收业务流程，再提高题库质量、扩大采集并上线岗位准备页。JD 和面经服务于探索，不构成录用标准；不以知识点全覆盖、总分或候选使用率为成功指标。

推荐顺序：阶段 0 基线与样例 → 阶段 1 证据契约 → 阶段 2 动态面试 → 阶段 3 画像与记忆 → 阶段 4 标准题映射 → 阶段 5 定时采集与统计 → 阶段 6 准备页 → 阶段 7 灰度校准。

阶段 4 的图谱与缓存修复可在阶段 0 后独立推进；标准题映射需对齐阶段 1 的评价依据。不要等待全库归一才验证动态面试，也不要先扩大采集再发现评价方向错误。

全链路首个可用版本截止阶段 3：使用少量审定候选，支持完整对话和有依据的画像。完整岗位数据产品需完成阶段 6。

## 2. 当前基线与并行工作边界

代码核对以 2026-10-10 当前工作区为准，包括未提交改动。实施阶段 0 必须重新记录提交版本及相关工作区差异，不能假设本次快照就是上线版本。

| 现有基础 | 当前限制及关联位置 |
| --- | --- |
| 面经同步、清洗、持久化 | `experience/service.js` 请求触发后台执行；需要任务恢复和版本化去重 |
| 知识图谱与向量题组召回 | `knowledge-graph.js`、`embedding-cache.js`、`recall.js`；需修复自环、重建失败覆盖、缓存一致性及归一问题 |
| 关键词队列、候选追问与模型分析 | `interview/turn-service.js`、`llm-service.js`；仍有弱项驱动和固定关键词推进逻辑 |
| 固定四维评分契约 | `agent-runtime/interview-runtime.js` 及 Codex 评价校验；必须与新业务结果一起版本化 |
| 长期记忆和上下文摘要 | `interview/context-service.js`；现有稳定弱项、岗位适配信号需调整 |
| Runtime 及事务提交改造 | 工作区已有 Codex、`turn-commit.js` 等并行变更，复用并协调，不覆盖或重做 |

本计划负责业务语义、题库与产品流程；[Runtime 实施清单](../architecture/todolists/agent-runtime-openviking-implementation-todolist.md)负责执行器、隔离和运行可靠性。先在一个已验证可用 Runtime 打通新业务契约；其他 Runtime 未通过相同契约验收前不启用新模式。生产 PostgreSQL、租约和多副本结果不得由 SQLite 或单进程测试替代。

## 3. 阶段 0 建立基线和评估样例

**交付物**

- [x] 记录当前本地 Runtime、存储、路由和关键版本；线上配置未核验，不作已部署声明。
- [ ] 固定最小业务样例集：优势回答、明确错误、含糊回答、替代解法、提示后答对、沿回答转向、主动跳过、无 JD、系统失败、旧画像被新证据纠正。
- [ ] 为每个样例人工标注允许的判断、必须保留的证据、禁止外推的结论、可接受的下一步动作集合。
- [x] 定义验收记录模板：代码版本、数据样例、Runtime/模型/规则版本、执行环境、结果、失败项和回退验证。

进展：10 类合成样例已落盘，包含允许动作、证据要求和禁止推断；由 Agent 提议，尚未人工审定。现有 91 项 API 测试通过，真实模型比较与异常记录见验收报告，不将结构测试当作语义正确率。

**验收**：每个样例可以解释为什么某个动作合理，不以单一固定措辞作为答案。对现有链路跑基线并保存真实差距；不伪造改进前数据。确认未涉及项不应扣分、技术正确性不由 JD 决定等硬边界。

**进入下一阶段**：样例、证据格式及新旧兼容范围明确。尚未执行的检查保持未完成状态。

## 4. 阶段 1 证据评价契约与存储

**交付物**

- [x] 定义版本化轮次结果：输入意图、能力观察、证据引用、适用维度、帮助程度、待核实项和建议动作。
- [x] 每条观察保留轮次与回答依据，区分自述、回答表现与模型假设；当前没有可信工具证据，因此禁止生成工具已验证结论。允许不适用、证据不足和空观察。
- [ ] 定义题目评价依据：目标、约束、关键点、替代方案；先为样例候选维护小型规则集，不依赖全库改造。
- [ ] 增量数据库迁移和读取适配，新记录按版本读取；旧分数不冒充新证据，不自动重写历史画像。
- [ ] 更新选定 Runtime 的提示、解析、Validator、服务端响应和最小前端展示，避免只改 Prompt。取消新模式的固定岗位匹配扣分与强制缺点。

进展：独立 native-api 影子入口、Validator、SQLite 存储、PostgreSQL migration、读取接口及最新轮次证据面板已实现；默认关闭，不改变旧评分与队列。109 项测试通过，前端类型检查通过。PostgreSQL 尚未执行、浏览器尚未验收、语义仍需校准，因此存储与完整产品验收项保持未完成，不进入阶段 2。

**验收**

1. 正确但未提 JD 的技术回答不因此扣分；没有证据支持弱点时允许空列表。
2. 不存在的轮次或题目引用、跨用户引用被拒绝；无效结果不写入正式状态。
3. 提示后答对与独立答对具有不同记录；系统检索失败不形成用户弱点。
4. 老会话仍可查看，新模式不依赖伪造四维分数满足旧校验。
5. 在目标存储上验证迁移和事务；先影子运行，与旧路径分开保存，不触发双重推进。

**进入下一阶段**：契约样例通过，前后端能读取新结果；支持停用新模式，已有新会话仍由兼容读取器展示。

## 5. 阶段 2 动态探索与候选优先

**交付物**

- [ ] 增加当前方向、待追问线索、待返回话题、已获得证据、预算与结束原因。
- [ ] 动作拆为目的和话题走向，支持优势深挖、澄清、沿回答转向、换方向与结束。
- [ ] 先判断继续提问的价值，再召回或选择题目。可复用现有题组和少量审定候选，不等待全局标准题。
- [ ] 候选经过目标、难度、上下文、重复检查后优先使用；支持保留意图的改写和有理由的自拟。
- [ ] 后端校验并提交动作，沿用正在改造的原子提交边界；轮次重试、取消、旧快照不得重复推进。
- [ ] 区分模拟与教学的反馈时机，保留提示及答案揭示记录。

**验收**

1. 高质量回答可以触发进一步验证，无需先出现低分或弱点。
2. 首屏回答提到 hydration 时，可转向深挖并保留返回线索；随口提词不强制转向。
3. 有合适候选时使用或改写候选；没有适合候选时允许自拟并说明原因，不能硬选。
4. 未问完方向列表也可合理结束；用户跳过不自动记为不会。
5. 同一轮重复请求只产生一次有效推进；断开、超时、非法结果不留下半提交状态。

**进入下一阶段**：完整多轮场景可执行，阶段 0 样例的动作落在人工认可集合内；没有重大重复提问或越权提交问题。

## 6. 阶段 3 画像复盘与可修订记忆

**交付物**

- [ ] 会后展示优势、发展方向、不确定项、未涉及内容和可选练习建议，每项可展开依据。
- [ ] 区分本场观察与跨场趋势；不输出岗位通过或录用概率，不用总分比较难度不同的自适应会话。
- [ ] 摘要保存证据引用、帮助程度、矛盾及已解决线索；历史 stable 字段仅作历史记录。
- [ ] 支持修正事实、忽略旧观察和删除个人记录；模型摘要不充当新独立证据。
- [ ] 建议兼顾巩固优势和验证未知项，避免旧弱点不断决定后续题目。

**验收**

1. 只聊性能优化的短会话仅生成对应局部画像，算法等未问项不产生评分。
2. 同一项目连续追问不伪装成多份独立经历证据；未执行代码不声称已验证运行结果。
3. 新证据与旧印象冲突时允许修订，并能找到修订依据。
4. 摘要压缩、再次进入面试后，提示记录和不确定性仍在，不退化成确定弱项。
5. 删除或忽略记录后，后续检索和画像不再使用相应内容；验证用户隔离。

**阶段成果**：可以灰度验证“动态面试 → 证据画像”的产品价值，无需先建成岗位榜单。完成此阶段仍不代表新 Runtime 已满足生产可靠性条件。

## 7. 阶段 4 图谱修复与标准题映射

**交付物**

- [ ] 修复分类自环、失败重建覆盖、别名误归一、入库前缓存更新和删除后残留向量等已发现问题；明确分类和相关关系边界。
- [ ] 稳定知识点 ID、标准题、题目考点多对多关系、原始题映射与审核候选。
- [ ] 图谱限定候选并补充全局召回，再判断题目意图与约束是否等价；没有匹配进入候选池。
- [ ] 接入标准题评价依据；保留来源、版本、合并重定向及可恢复的审核记录。
- [ ] 用精选历史面经小批量回填，验证后逐步扩大；现有个人题库来源引用保持可读。

**验收**

1. “闭包定义”和“闭包应用”保持独立；两种等价定义问法可映射同一题。
2. Hooks 过期闭包题可从两个考点找到，结果按标准题 ID 去重。
3. 不同代码约束不误合并；低置信度不直接创建正式题。
4. 并发提交完全相同候选不创建两条正式记录；语义重复经审核合并后来源仍可追溯。
5. 重建失败保留旧图；重新清洗和删除后旧向量不占用召回名额。
6. 标注样本分别统计误合并与漏匹配，不能只报告总体准确率；关键约束误合并为阻断项。

**进入下一阶段**：小批数据可重跑、纠错，映射和题目质量可解释；大规模历史回填在此之前不开展。

## 8. 阶段 5 定时采集与可信统计

**交付物**

- [ ] 持久化调度、任务阶段、原文版本、处理版本、租约及有限重试；明确时区、数量上限和模型预算。
- [ ] 来源 ID 与内容指纹去重，内容更新可重新处理；转载归组保留来源。
- [ ] 数据库提交成功后更新派生索引，统计按有效事实重算或可追溯刷新，不靠盲目加一。
- [ ] 巡检任务完成情况、来源失败、重复率、分类缺失、数据新鲜度和处理成本。
- [ ] 按岗位与时间过滤，按面经重复组聚合考点，显示来源范围、样本量、覆盖率与统计更新时间。

**验收**

1. 同一调度重复触发、Worker 重启和任务重试不重复入库或计数。
2. 原文不变跳过重复模型处理；正文变更只替换有效新版，不叠加旧统计。
3. A、A 的转载 B、独立经历 C 均考闭包时，考点贡献为 2；同篇多题仍只计一次。
4. 时间未知数据不混入近 30 天统计；采集失败不显示为“该岗位没有题目”。
5. 在实际 PostgreSQL 和目标部署副本条件下验证领取、租约过期和竞争，不能以本地单进程替代。
6. 模型超时、来源异常可定位和恢复，预算耗尽停止新增模型工作而保留原文。

**进入下一阶段**：统计可由来源复算，重跑结果一致，异常和恢复均有记录。

## 9. 阶段 6 岗位准备页与会话快照

**交付物**

- [ ] 接入 JD 要求、近期面经观察、准备画像三块，分别标明来源。
- [ ] 同岗位不足时可用明确标识的相似岗位参考；无 JD 可通用探索，无面经可按 JD 或用户方向继续。
- [ ] 用户修正输入、选择模式和预算，确认后绑定准备快照进入阶段 2 的动态面试。
- [ ] 提供原文证据、例题和已练习标识；页面不展示伪精确岗位通过率。

**验收**

1. JD 明示要求与模型推断可区分，能力判断能追溯到用户证据。
2. 相似岗位样本不会标成目标公司实际考题；样本不足不生成确定趋势。
3. 用户修改 JD/简历后旧分析标为需更新，开始时绑定已确认版本。
4. 重复点击开始仅创建一个会话；中途样本刷新不静默改变初始快照。
5. 从页面完成一次多轮面试和复盘，报告范围、选题来源与实际过程一致。

**进入下一阶段**：真实页面流程通过，局部失败可降级，用户能理解这是准备参考而非招聘判决。

## 10. 阶段 7 小范围灰度与持续校准

- [ ] 先内部合成或获准样例，再小范围真实用户；按会话版本固定策略，提供停止新模式的开关。
- [ ] 对新增 Runtime 跑相同业务契约及端到端样例；厂商切换不改变能力画像语义。
- [ ] 监测无依据结论、证据引用错误、重复提问、错误合并、停止合理性、用户纠正及延迟成本。
- [ ] 规则和 Skill 变更先离线评估，再小范围发布，保留版本与回退；不自动修改生产策略。

**验收门槛**：跨用户泄露、伪造证据、重复正式提交及把未涉及项判为失败属于阻断项，出现即停止扩大灰度。其他质量指标在阶段 0 固定基线、灰度前确定阈值，用同一组保留样例比较，不在看到结果后更换口径。不能以“测试通过”替代真实模型质量或线上可靠性验收。

回退优先停止新会话使用新策略，保留新数据与可读性；进行中的会话按其版本继续或明确结束，不能静默切回旧规则。数据库采用兼容增量迁移，不以删除新记录作为回退。

## 11. 暂缓事项

第一轮不引入图数据库迁移、全程自主采集 Agent、多 Agent 编排、全岗位全题库覆盖、自动录用预测、自动合并所有语义候选。先验证业务效果和数据质量，再决定是否增加基础设施。

阶段 0/1 的实际进展以本次验收记录为准，后续阶段尚未实施；逐项记录事实并更新勾选，避免沿用其他专项的完成状态。
