# 岗位分析与面试准备页设计

- 版本：v0.2
- 日期：2026-10-10
- 状态：设计草案，尚未实现；页面路由、接口和数据字段在实施阶段确认。

## 1. 定位与目标

在 JD 解析完成后、正式模拟面试之前，提供岗位分析与面试准备页。结合 JD、近期面经、用户简历及历史练习证据，帮助用户了解岗位要求、面试考察方向和自身准备情况，再由用户选择是否按该 JD 进入面试。

页面同时产出本次面试的准备快照，为面试 Agent 提供可调整的探索方向、候选题范围、用户能力证据和时间预算。目标是通过动态对话发现优势与发展方向，形成供用户参考的画像，不要求遍历所有知识点，也不根据 JD 推断企业内部录用标准。页面分析不会自动启动面试。

本方案承接面经采集、去重、考点归一和标准题映射的设计；这些能力是数据依赖，不因本方案存在而视为已经完成。现有知识图谱用于辅助候选召回，不能单独证明题目同义或用户能力。

## 2. 用户流程

1. 用户选择或上传 JD，选择用于本次分析的简历。
2. 系统提取岗位要求，匹配近期面经，并整理用户已有能力证据。
3. 用户查看岗位要求、近期考点和准备画像，可修正岗位、级别及经历识别结果。
4. 用户选择模拟面试、能力摸底或专项练习，确认时长与关注方向。
5. 系统固定本次准备快照，创建面试会话；用户也可以暂不进入面试。

## 3. 页面内容

### 3.1 岗位要求

展示核心职责、必备能力、加分项和预期级别。每项要求关联 JD 原文片段；显式要求与模型推断分开标识。JD 未明确级别时允许用户确认，不强行给出确定级别。

### 3.2 近期面试参考

展示高频考点、典型问题、追问深度和可用的近期变化。支持时间范围筛选，展示样本量、来源、更新时间和匹配范围。

面经匹配优先级：同公司同岗位，其次相似岗位。扩大检索范围必须展示“相似岗位参考”，不能将其归为目标公司实际面试情况。招聘类型、岗位级别等筛选条件需要保留，不能将实习、校招、社招样本无提示混合。

近期统计以面经发布时间为准，抓取时间用于标识更新状态。发布时间不明的数据不进入有明确时间窗口的榜单。

考点出现率按去重面经计算：分子为包含该考点的有效面经重复组数，分母为相同筛选范围内满足统计质量要求的面经重复组数。同篇多道题涉及同一考点只计一次；父级汇总取来源并集。展示可统计覆盖率，不能将处理失败或未分类默认为没有该考点。

这里的出现率仅描述采集样本，不能称为整个市场或目标岗位的真实考察概率。趋势只在相同口径、可比时间窗口且样本足够时展示。最低样本阈值需依据实际数据校准，未校准前不输出确定的趋势结论。

### 3.3 岗位难度参考

第一版不输出缺少依据的综合难度分，按以下维度展示要求和例题：

| 维度 | 展示内容 |
| --- | --- |
| 知识深度 | 基础理解、原理解释、设计与权衡 |
| 实践要求 | 项目细节、排障、性能优化、实际职责 |
| 编码要求 | 手写实现、算法、约束与复杂度 |
| 综合要求 | 架构、业务理解、协作与方案决策 |

分别标注“JD 预期要求”和“近期面经观察”。面经反映已报告的问题及追问，不能直接推断真实录用门槛。题目难度分类需要题目内容或经过审核的元数据支持。

### 3.4 我的准备画像

准备画像是针对本次岗位的证据整理，不是对用户的固定能力标签。

| 状态 | 含义 |
| --- | --- |
| 经历已体现 | 简历或用户补充中有相关经历描述 |
| 已有能力证据 | 历史面试或练习回答提供了局部判断依据，标明时间、场景及是否使用提示，不等同于全面认证 |
| 待验证或待补充 | 尚无足够信息，不能据此判断不会 |

示例：JD 重视性能优化，简历包含首屏优化项目，但暂无回答证据验证指标选择、瓶颈定位和方案权衡，应展示为“经历已体现，能力待验证”。

用户可以纠正简历解析或经历归属；自述补充仍标为用户陈述，与作答或执行证据区分。历史证据标注时间与适用范围，存在矛盾时中性核实，不预设旧结论正确。无简历或历史记录时允许继续，仅展示可用信息，不生成伪完整画像。

不输出录用概率，不将简历未提及、面试未覆盖和能力不足等同。

## 4. 面试入口与控制

| 模式 | 目标与行为 |
| --- | --- |
| 按该岗位方向模拟面试 | 以 JD 为场景参考，结合近期面经和用户回答动态探索，不输出岗位通过结论 |
| 先做能力探索 | 从用户经历与兴趣出发，发现优势、核实不确定项，动态调整深度 |
| 专项练习 | 用户可以选择巩固优势或补充不足，允许提示与讲解，并记录帮助程度 |

开始前确认参考级别、时长、模式和关注方向。用户可以跳过、转向或结束；系统说明本次探索范围，不能将未涉及项计为低分。JD 是可选的定向背景，通用能力探索不应依赖先提供 JD。

## 5. 与面试 Agent 衔接

### 5.1 准备快照

下表为建议的数据内容，不是已经发布的接口契约。

| 内容 | 保存信息 |
| --- | --- |
| 输入版本 | JD、简历及用户修正版本 |
| 岗位要求 | 能力要求、优先级、原文依据、推断标识 |
| 面经依据 | 来源或版本引用、筛选条件、时间范围、样本量、统计口径与匹配范围 |
| 准备画像 | 能力项、证据引用、时间、提示记录、待验证项 |
| 用户选择 | 模式、目标级别、时长、关注方向 |
| 探索计划 | 初始方向及选择理由、预算、候选题引用、待验证线索；方向可调整，不是必考清单 |
| 生成信息 | 快照版本、生成时间、模型及规则版本 |

会话绑定确认后的快照。后续面经更新不静默改变已开始会话的初始依据；面试中的能力判断另行更新。原始来源被修订时保留可追溯的版本或证据摘录。快照和画像按用户隔离，不能混入其他用户的私有经历与练习记录。

### 5.2 动态面试策略

每轮先提取回答证据，更新能力判断，再决定动作和选题。动作分为两个维度：

- 考察目的：澄清、深入、验证、拓展。
- 话题走向：留在当前考点、沿回答转向、切换到计划考点；也可以结束面试。

候选人提到新话题时，判断其岗位相关性、实际参与程度和深挖价值，可加入待追问列表；必要时记录待返回考点，避免无边界转向。

题目选择优先级为：满足当前目标的候选原题、保留考察意图的候选改写、无合适候选时自拟。候选须通过相关性、难度、重复考察及上下文完整性检查。改写改变关键约束时需重新检查评价依据。

JD 和近期高频考点提供初始优先级，不构成强制覆盖清单。Agent 优先选择能补充能力证据、核实优势或澄清不确定性的题目；既允许深入优势，也允许探索相邻方向，避免只追弱项或只问熟悉领域。选择依据需可追溯，不以最大覆盖率为目标。

获得足够证据、继续追问没有新增信息、用户希望转向或预算不足时，退出当前分支。结束无需等待计划全部完成，未探索方向保留为未涉及。

记录动作、考察目标、触发回答、题目来源、候选 ID 和自拟原因。自拟题先保留在会话中，经审核后再进入正式题库。后端校验候选引用、重复提问、追问预算及轮次幂等性。

最终画像展示本次优势、值得继续发展的方向、不确定项、本次未涉及内容和可选建议。每个判断引用回答证据、适用场景及帮助程度；提示后完成不等同于独立完成。题目评价规则用于判断具体回答，不输出整场通过或不通过，不将局部表现外推为全面能力结论。

评价维度按问题目的选择，允许不适用或证据不足；不要求每道题都评价岗位匹配、表达、原理和实践。用户陈述、模型解释和可执行验证分开记录。完整的评价、记忆和复盘演进见[动态面试与能力画像全链路设计](adaptive-interview-evidence-profile-spec.md)。

## 6. 后端职责与异常状态

后端分别负责岗位要求提取、面经检索统计、个人证据整理、准备快照生成和会话创建。模型负责语义分析与建议；来源过滤、权限、计数、版本绑定和状态提交由程序保证。

| 状态 | 页面行为 |
| --- | --- |
| JD 解析失败或关键信息缺失 | 提示补充或修正，不伪造岗位要求 |
| 同岗位样本不足 | 标注不足，可展示明确标识的相似岗位参考 |
| 没有近期面经 | 允许基于 JD 和已有题库开始，说明缺少近期样本 |
| 部分分析失败 | 分区展示成功结果与失败状态，允许局部重试 |
| 用户修改 JD 或简历 | 将相关分析标为需更新，重新确认后生成新快照 |
| 重复点击开始或网络重试 | 同一次开始请求幂等处理，返回同一会话 |

## 7. 第一版范围与验收

第一版完成一页流程：岗位要求摘要、近期考点及来源、个人准备情况、确认并开始面试。优先使用现有能力可支持的数据，缺失项显式降级。

验收场景：

1. 岗位要求可以回到 JD 原文；推断内容有明确标识。
2. 面经来源、样本范围、时间窗口和去重口径可查；重复导入不增加统计。
3. 扩大为相似岗位检索后，页面明确显示范围变化。
4. 没有历史记录时，画像显示待验证，不生成虚构弱项或录用概率。
5. 用户修正输入后，快照依据同步更新；未主动开始不会创建面试会话。
6. 按 JD 方向开始的会话绑定确认快照，初始探索方向及选题来源可追溯，不生成岗位通过结论。
7. 同一会话允许沿回答转向、深入优势或提前结束，遵守预算，不要求完成知识点清单；未涉及项不扣分。
8. 样本不足、局部失败、重复开始请求都有明确且一致的行为。

实施前需结合真实数据确定样本阈值、岗位匹配规则，并细化页面路由、快照存储和接口契约；这些细节不影响本方案中的来源边界与面试决策原则。
