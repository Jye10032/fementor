# 动态面试与能力画像全链路设计

- 版本：v0.1
- 日期：2026-10-10
- 状态：设计草案，尚未实现。本文定义产品与业务演进方向，不代表已有评分、状态机或记忆字段已经迁移。

## 1. 目标与边界

通过动态对话理解用户在具体场景中的能力，提供有证据的优势、发展方向和不确定项。JD 与近期面经提供探索背景，不代表团队内部录用标准；系统不预测通过、不输出录用概率，不以问完知识点清单为成功条件。

保留题库和知识图谱的候选召回能力。Agent 根据回答决定继续、转向或结束，满足目标的候选题优先，允许改写和必要的自拟。评价仍需准确、具体；突出优势不意味着一味肯定，明确的技术错误可以指出，但不能从一次错误推导整个人的稳定弱点。

## 3. 全链路职责

### 3.1 采集与统计

面经是选择性公开的自述样本，频次用于备考参考，不等于招聘标准。按来源、时间、岗位、级别和独立样本量展示范围；转载去重，不把独立候选人遇到同题去重成一条经历。

保留没有成功分类的样本数量，避免把处理缺口当作该考点不重要。新增来源或采集关键词改变时，标记统计口径变化，不能把采集策略变化直接展示为招聘趋势。

### 3.2 知识图谱与标准题

图谱负责相关候选召回，不负责决定必考顺序，也不代表由父到子难度递增。题目映射须保留场景、约束、代码及来源，不能把不同考察意图仅因知识点相同而合并。

标准题评价依据包括考察目标、适用条件、关键正确性要求、合理替代解法、可观察的深入证据和追问建议。不是唯一标准答案，也不是关键词命中表。缺乏可靠评价依据的题可用于经历澄清，但不产生确定的技术能力评分。

### 3.3 准备页面

展示 JD 背景、近期面经观察、用户已有证据和可选探索方向，见[岗位分析与面试准备页设计](job-interview-preparation-spec.md)。用户可修正经历、选择巩固优势或探索陌生领域，不必提供 JD 才能开始通用面试。

不要在入口提前展示本次将出的具体题目与答案，再把答对视为独立掌握。备考页允许查看例题，但需要记录已练习或已揭示答案的题目，后续可用变式检查迁移能力。

### 3.4 每轮观察与决策

建议流程：输入意图识别 → 提取证据 → 更新本场观察 → 选择探索动作 → 召回候选并择题 → 校验并提交。

输入先区分回答、澄清、反问、跳过、纠错和结束。问题本身不完整、检索失败或 Agent 评价依据不足属于系统不确定性，不能写成用户能力不足。

每轮保留回答片段及轮次引用，区分：用户声称做过、解释显示理解、实际执行得到验证、模型提出假设。技术判断依据与用户能力依据分别记录：文档能支持某个技术结论，不能证明用户掌握了它。

探索动作由两个维度组成：目的为澄清、深入、验证或拓展；走向为留在当前方向、沿回答转向或切换其他方向。结束是独立动作。相关话题只提供机会，不自动触发转向。

维护可调整的方向列表、当前分支、待追问线索、待返回话题、已获得的证据和剩余预算。记录动态调整理由，不把列表实现为必须消费完的题目队列。

### 3.5 候选选择与退出

先判断是否值得继续提问，再选题。考虑预期新增证据、用户意愿、难度适配、上下文完整性、重复程度与时间成本；题目热度只作为参考。

适合当前目标的候选原题或改写优先于自拟；不设置强迫使用题库的硬比例。改写后变化的约束需更新评价依据，自拟题不自动进入正式库。

不要反复证明初始印象：既用场景变式验证已观察到的优势，也在用户愿意时尝试相邻方向。不能将不同问题中的同一考点一律视为重复；需判断是否产生新的能力证据。

继续追问无新增信息、用户希望跳过、当前分支已足够清楚或预算不足时退出。用户拒绝某方向不等于不会；未问完计划不阻止结束。

### 3.6 评价与反馈时机

通用能力维度提供词汇，题目级规则提供判断依据；仅评价本题适用的维度。不将岗位关联程度作为技术回答的统一扣分项，不强制每轮填写优缺点。

允许多种正确方案。术语不标准、表达简短不自动代表技术薄弱；表达能力只有在题目目标相关且证据充分时单独讨论。不得仅凭口头描述宣称代码运行、性能收益或项目职责已被验证。

模拟面试默认避免在后续验证前揭示完整答案，主要反馈集中在结束时；教学练习允许即时提示与讲解。记录帮助程度、答案是否已揭示和重复练习情况，避免把提示后复述当成独立能力。用户可以主动请求反馈。

### 3.7 画像与复盘

画像包含：本次优势、可发展方向、不确定或矛盾项、本次未涉及内容、可选行动建议。每项关联具体证据、发生时间、题目场景和帮助程度。多轮共用一个案例不自动算多份独立证据。

区分本次观察和跨场趋势。自适应面试问了不同难度、不同数量的题，简单平均分不能可靠代表进步或人与人排名；比较时需要相近条件或专门的校准题。第一版以证据和描述为主，不使用整场总分生成录用判断。

不要求每场产出全面画像。短场次可以只支持少数局部结论；报告必须保留范围，不以格式完整为由补造优势或弱项。

### 3.8 长期记忆与后续练习

建议观察记录包含能力项、陈述、证据轮次、支持或反对证据、适用范围、帮助程度、时间和修订状态。摘要只作为索引，不能替代原始证据。

后续新证据可以修正旧判断。提供事实纠正、忽略旧观察和删除个人记录的入口；不以固定弱项反复支配后续面试。画像更新不能把旧模型结论再次当作新的独立证据。

后续建议同时支持优势深化、迁移练习、不确定项验证和用户兴趣探索。自拟题、用户回答和复盘结论不自动进入公共题库，正式题库仍需要来源与质量审核。

## 4. 状态与工程保障

初始准备快照保持可追溯，当前探索状态逐轮更新，两者分开。每轮观察、题目选择和状态推进以同一轮次标识提交，网络重试不重复出题或计证据。模型产生的建议须经后端校验后生效。

模型输出需要引用存在的题目与证据，不接受凭空来源；检索或评价失败允许降级为澄清或暂停评价，保留旧的有效状态。上下文压缩必须保留关键证据引用、提示记录、待核实矛盾及已解决线索，避免只留下负面摘要。

现有固定评分字段不能仅重命名后沿用旧含义。实施时引入版本化评价结果，兼容历史会话；各 Runtime 遵循同一业务契约，客户端对旧数据明确标识为历史评分。

## 5. 验收与优先级

### 优先处理

1. 统一页面、提示与画像措辞，取消自动岗位通过判断、强制覆盖及强制缺点输出。
2. 定义带证据引用的观察和动态动作契约，并同步运行时校验及前端展示。
3. 支持优势深挖、沿回答转向、合理结束和提示记录。
4. 调整记忆生成与上下文摘要，防止单场弱项固化。
5. 完善题目规则、样本统计和候选质量，再扩大自动化规模。

### 评估场景

- 候选人展现优势后，可深入确认，不必先产生低分或弱项。
- 没有涉及某知识点，报告不扣分、不虚构评价。
- 用户提出合理替代解法，系统按约束评估，不按答案关键词机械扣分。
- 系统检索失败、题目有歧义，画像不会新增用户弱点。
- 模拟中转向新话题，记录原因，仍可返回或结束。
- 同一道题答案已揭示后再次答对，不能升级为独立掌握证据。
- 新回答推翻旧印象，画像可修订，历史结论不反复污染后续判断。
- 短场次只产生局部画像，不要求填满能力表。
- 同一轮重试不会重复创建题目或扩大证据数量。

评估重点是证据引用正确性、无依据结论比例、追问新增信息、重复提问、合理停止与用户可理解性。知识点覆盖率、候选使用率和面经热度可用于诊断，不能单独作为产品成功指标。实施前需用人工审定样例校准，具体阈值由评估结果确定。
